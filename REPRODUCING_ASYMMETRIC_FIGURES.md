# Asymmetric tournament figures

This technical note describes the original working files. In a source-only
checkout, generate the RDS and CSV inputs with the relevant stage of
[reproduce.R](reproduce.R) before using a redraw command.

Run the R scripts from this folder. Only base R is needed.

For an exploratory strategy map, open `05_explore_asymmetric_tournaments.R`,
edit `settings` at the top, and source the file. Set `mode` to `"fixed"`,
`"responsive"`, or `"both"`. By default it draws in R's plotting window,
without a legend or any file exports. Set `legend=TRUE` to add the optional
legend, `png=TRUE` to save the PNG, and `pdf=TRUE` to save the vector PDF.
These switches are in `settings` and are also arguments of `explore_asymmetric()`.
The sidebar explanation is not printed on the figure.
After sourcing, a particular talent pair can be queried with, for example:

```r
result$optimal_investment(alpha1=1, alpha2=1, state="fixed")
```

The returned `x1`, `x2`, and `utility` describe one optimal allocation.
At a tie, more than one allocation may be optimal. This tool requires
`05_asymmetric_model.R`, `05_random_allocation_reference.R`, and
`05_linear_population_means.R`, all supplied
in this folder. Training exponents must be between 0 and 1; spoils exponents
and the total budget must be positive.

The fixed reference is an infinite population with uniform random allocations
independent of talents: X1 is uniform on [0,B] and X2=B-X1. Thus E1=E2=B/2.
Each M is computed separately by `random_allocation_reference()`. For phi=1
its expectation is analytical. Otherwise, talent is integrated by GaussÃ¢â‚¬â€œHermite
quadrature and time by adaptive one-dimensional integration. The default talent
distribution has median 1 and original-scale standard deviation 0.5.

Responsive calculations use population best responses to seek a consistent
ratio (E1/M1)/(E2/M2). This updates both E and M. The printed population table
contains the inputs to each map. Side bars and the separately printed response
means show the investments generated by its optimal choices: a first response
to the random reference in the fixed row, and self-consistent investments in
the responsive row. First-response means are not fed back into the fixed map.

When both phi values equal 1, `05_linear_population_means.R` instead uses exact
one-dimensional normal-tail integrals for both first-response means and the
equilibrium. Numerical integration and scalar root finding remain necessary,
but no talent quadrature or investment grid is needed for these means.

The model engine uses the same global specialization-boundary calculations as
the main Script 05. Interior allocations and population best responses use
investment grids. Increase `nx`, `nxpop`, `nroot`, and `nquad` to check numerical
resolution, especially near switches between competing optima. Point queries
refine each grid-detected local maximum before comparing it with the endpoints.
The equilibrium routine stops if its search does not find a single bracket;
it does not assume that repeated population responses converge.

The established figures can be redrawn with:

```r
source("05_asymmetric_tournaments_figure_HDR.R")
source("05_asymmetric_tournaments_utility_contours.R")
source("05_many_tournaments_and_asymmetric_linear.R")
```

The utility script also requires `00_helper_functions.R`. Its PNG shows actual
utility under the population scalers. Its companion caption draft explains
why mean utility equals B at self-consistency but need not do so for a first
response to a fixed random population.

The bridge figure also uses the two supplied participation summary CSV files
under `Etude3_multiple_tournaments_analysis`; their reproduction instructions
are in `REPRODUCING_PARTICIPATION_FIGURES.md`.

`05_asymmetric_tournaments_figure.R` contains a different set of example
parameters and writes the same PNG filename as the HDR script. Run the HDR
version last to restore the manuscript's four-scenario figure. The saved
`Figure_asymmetric_tournaments_strategy_map_HDR.png` is the HDR version.

The explorer exports PNG and vector PDF versions only when their respective switches are TRUE. It draws specialization
regions as polygons bounded by its computed
global tie curves; their edges are independent of the allocation raster's
pixel boundaries. Parameter labels use Greek beta and varphi.

For the new parameter-space geometry figure, run
`05_equal_talent_5050_parameter_space.R`. It uses the supplied
`05_equal_talent_geometry_inputs.rds` and writes PNG and PDF outputs plus a
CSV of geometric classifications and crossing coordinates. Fixed-reference
population weights are recalculated from random allocations. Nonlinear
responsive ratios start from the existing Script 06 calculations;
the linear responsive panel uses the exact one-dimensional population formulas.
The corner beta1,beta2 >= 0.70 with phi1=phi2=1.5 is refined using smooth, continuous
endpoint-only population expectations plus a stratified QMC correction for
diversification. This removes discrete winner-count noise without assuming
that everyone specializes. The refinement is supplied as
`05_equal_talent_nash_refinement.rds`; it can be recalculated using
`05_refine_equal_talent_nash.R` and its supplied C++ source (requires Rcpp
and an R-compatible compiler). The numerical check script
`helper_05_verify_equal_talent_nash.R` checks four times as many conditional integration points in the main corner,
doubled points at its more demanding lower edge, a finer allocation grid,
and an independent adaptive integral. The refinement rebuild saves each completed
beta row, so an interrupted run can resume. Delete its checkpoint directory if
you change the integration algorithm.

The median-talent contour neighbourhood also uses deterministic conditional
integration, splitting the alpha2 integral at the global strategy switch.
This removes the remaining node-switching noise when only one beta is large.
The supplied `05_equal_talent_conditional_refinement.rds` is rebuilt by
`05_refine_equal_talent_conditional.R` and its C++ source. Run this **after**
`05_refine_equal_talent_nash.R` when rebuilding both. The selected region is
saved in `05_equal_talent_conditional_selection.rds`; keep that file when
resuming. `helper_05_verify_equal_talent_conditional.R` checks doubled orders
of both quadratures and a finer allocation grid. Drawing the supplied cached
figure needs neither Rcpp nor a compiler.

In `05_equal_talent_5050_parameter_space.R`, increase `gradient_legend_drop`
to move the complete bottom gradient-legend row lower; use zero to restore its
previous position. This changes only the plotting layout. After rebuilding the
numerical inputs, regenerate the geometry cache with:

```r
Sys.setenv(RECOMPUTE_5050_GEOMETRY="1")
source("05_equal_talent_5050_parameter_space.R")
Sys.unsetenv("RECOMPUTE_5050_GEOMETRY")
```

The input file can be regenerated with
`05_prepare_equal_talent_geometry_inputs.R` when the original responsive
Script 06 cache is available. All input metadata are retained in that RDS.

The geometry concerns the stationary equal-marginal-return curve. Hatching
marks crossings at which 50:50 is not globally optimal. Such a crossing is
not a smooth switch of the globally optimal allocation through 50:50.
For the displayed phi combinations this curve is monotone relative to the
equal-talent diagonal and has at most one crossing. The geometry helper
rejects unequal phi pairs lying strictly on the same side of 1, because those
can have two crossings and need a more general classification.


The companion population-energy figure is drawn by
`05_energy_allocation_parameter_space.R`, using the supplied
`05_energy_allocation_inputs.rds`. It writes
`Figure_energy_allocation_fixed_vs_responsive.png` and its vector PDF.
Panel dimensions, arrangement, fonts and examples follow the equal-talent
parameter-space figure. The two scales on the common colour bar give E1 and
E2 in budget units (E1+E2=B=50), not utilities. The left block shows the
first response to the random-allocation reference; the right block shows
self-consistent population investments. The same unfilled A-D polygons
classify the change between these two states. Full definitions are in
`Figure_energy_allocation_caption.md`.

To rebuild the numerical fields, run
`05_prepare_energy_allocation_inputs.R`. This requires the supplied
`05_energy_allocation_population.cpp`, `05_energy_allocation_quadrature.R`,
the existing random-reference helper and the geometry input RDS, plus Rcpp
and an R-compatible compiler. The geometry ratios are starting guesses only;
the energy builder checks and refines the population-consistency equation.
Each completed beta row is cached so an interrupted run can resume. The
builder exposes quadrature orders, allocation resolution and `beta_stride`:
the default stride 2 uses 51 beta values from the original 101-value grid;
stride 1 uses all 101. Plotting interpolates energy fields and draws continuous
zero-contour polygon boundaries. Plot changes do not rerun population integrals.

The verification script `helper_05_verify_energy_allocation.R` checks higher
quadrature orders, a finer allocation grid, representative points in all four
feedback regions, exchange symmetry and independent adaptive integrals in the
linear case. The results are saved as
`05_energy_allocation_resolution_check.rds`. For manual layout changes, increase
`gradient_legend_drop` in the plotting script to move the complete bottom
energy scale lower. Example crosses can be toggled with `show_examples`.


The energy figure now prefers `05_energy_allocation_refined_inputs.rds` when
available. Run `05_refine_energy_allocation_boundaries.R` after the base energy
builder to regenerate it. This uses the supplied
`05_energy_allocation_population_refined.cpp`, splits conditional talent
integrals at specialist/diversifier transitions as well as the B/2 switch,
and refines the beta mesh near each A-D boundary. It also checks whether a
boundary moved outside the initially selected region and calculates extra
nodes as needed. The refined CSV flags directly recalculated nodes; only the
background away from the boundaries is interpolated from the base fields.
The higher-order verification and coverage checks are in
`helper_05_verify_energy_boundary_refinement.R`.

PNG exports default to 600 dpi while retaining the previous physical panel
sizes; `png_resolution` controls this. The A-D legend is a single row. Marker
size and letter size are controlled by `region_circle_cex` and
`region_letter_cex`. `05_energy_allocation_label_positions.rds` preserves the
previous label centres. Remove that optional file to place centres anew from
the current polygons. None of these drawing changes reruns the integrals.
